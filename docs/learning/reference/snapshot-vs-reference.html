Reference card

Freeze or Follow

When a row should copy a value, and when it should point at one.

The question

When the event happened, did it create a new fact, or did it just restate an existing one?

New fact → freeze (copy the value in).
Restated fact → follow (reference the source).

The two failure modes

MistakeWhat it looks like later
Followed when you should have frozen History rewrites itself. Last year's invoice reprints at this year's price. Nobody notices until an audit.
Froze when you should have followed The same thing splits into two. A rename leaves half the rows under the old name forever, and no report ever adds up again.

Worked examples

ValueCallWhy
Price on an order lineFreeze What they agreed to pay is a different fact from the catalogue price today.
Amount paid on a ContaFreeze You paid R$470. That is an event, not a description of the bill.
Tax rate on an invoiceFreeze The rate in force that day. Legally the past cannot move.
Shipping address on a shipped orderFreeze Where the parcel actually went. Not where the customer lives now.
Categoria of a ContaFollow A classification of the bill, not a fact about any one payment.
A Pagador's nameFollow Fixing a typo should fix it everywhere, not fork the institution in two.
A user's display nameFollow They renamed themselves. There is only ever one current answer.

The tell

Try saying the value out loud with the word “at the time” in it.

“The price at the time of the order” — that phrase names a real thing someone might ask about. Freeze.

“The Categoria at the time of the payment” — nobody has ever wanted that. They want to know what Moradia costs, using whatever Moradia means now. Follow.

Industry names

Warehouse people have called this Slowly Changing Dimensions since the nineties. Follow is Type 1 (overwrite, no history). Freeze — done by versioning the source rather than copying into the row — is Type 2. Knowing the numbers is mostly useful for reading other people's designs without having to reverse-engineer their intent. (Kimball)

In this codebase

Every materialised entries row freezes name and amount, and follows category_id. The null on category_id means inherit from the template, which is what makes recategorising a Conta move its whole history.
