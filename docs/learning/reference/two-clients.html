Which client?

The decision procedure, and the invariant that has to hold around it. From Lesson 02.

The three clients

ImportRuns asUse when
@/lib/supabase/client Publishable key · RLS applies Client Components, in the browser
@/lib/supabase/server Publishable key · RLS applies, bound to the caller Server Components, Route Handlers, server actions — the default
@/lib/supabase/admin service_role · BYPASSRLS Only when there is no session to bind to, or no write policy exists

Decision procedure

  1. Is there a signed-in user? No → admin, and authenticate the caller some other way (Bearer token). Yes → continue.
  2. Can RLS express what you need? Yes → session client. Stop here; this is almost always the answer.
  3. No — because the table has no write policy, or you need storage, or you must read across spaces? Then: resolve the space from the session first, and only then reach for admin.

The invariant

Any spaceId reaching admin-backed code must come from requireSession / resolveSession. Never from a form field, a URL parameter, or anything else the caller chose.

The shape to copy

download-report, in two steps that must stay in this order:

  1. User-session client looks the row up → RLS answers may they?
  2. Admin client mints the signed URL → does the thing they may.

Ask may they? with the client that can say no.

Route handler checklist

/api/* is excluded from the proxy, so nothing gates a route but the route. Every new one needs one of these on its first lines:

  • Machine caller — Bearer against CRON_SECRET, compared with timingSafeEqual, failing closed if the secret is unset.
  • Browser caller — auth.getUser() and 401 on null. Never getSession(): it does not revalidate the token.

Smells

  • An admin client in a file that never calls requireSession.
  • A spaceId parameter on an exported action reachable from a form.
  • A route handler whose first statement is not an auth check.
  • getSession() anywhere on the server.
  • A new table with RLS enabled and no policy written yet — that denies everything, which is safe but looks like a bug at runtime.
