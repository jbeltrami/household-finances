# Mission set: three strands, "comfortable with gaps"

João is learning through this repo on three fronts at once — TypeScript and
Next.js depth, data modelling and Postgres, and the engineering workflow
itself — with the underlying goal that hard calls get made from reasoning
rather than from copying whatever the last codebase did. He places himself as
comfortable shipping features and reading code fluently, but with fundamentals
that were absorbed by pattern-matching rather than derived.

## Implications

- Lessons can move fast and skip stack basics. The scarce thing is not
  *how*, it is *why this and not the obvious alternative*.
- Every lesson should name the gap it is filling, explicitly. Pattern-matched
  knowledge feels like understanding until it is asked to generalise, so the
  lesson has to say what was previously being run on instinct.
- Three strands is a lot for one workspace. Data modelling is the natural
  starting spine — it is where this feature actually lived, and both other
  strands hang off it (the TypeScript question is how to make a model
  unrepresentable-when-wrong; the workflow question is how a modelling
  decision gets recorded and sliced).

## Evidence

Stated directly when asked, after four rounds of design interrogation on the
Categorias feature in which he consistently engaged with trade-offs rather
than asking for the answer.
